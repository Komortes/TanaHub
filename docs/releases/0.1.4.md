# TanaHub 0.1.4 — Preview

This preview improves photo and cover loading, especially when opening a title from a large collection or using a slow connection. Packages include the .NET runtime; development tools are not required.

## Artwork and cover fixes

- Hidden catalog and library cards stop taking new image-loading slots while a title is open. Visible photos and covers load next; returning to the collection resumes its covers. Concurrent loads remain limited to four.
- Small title-header covers choose thumbnails or previews according to their displayed size and screen density. **Enlarge** still loads the original.
- **Refresh related titles** retries failed covers, including when the image URL is unchanged.
- Enlarged covers reserve a usable frame with **Loading cover…** while downloading. A failed image offers **Retry cover**, and a shared header/image failure keeps the viewer open for recovery.
- Retry and dismissal preserve keyboard focus. Background title-detail updates no longer close an already open cover when its original URL is unchanged.

Development tooling also updates to [Vite 8.3.3](https://github.com/vitejs/vite/releases/tag/v8.3.3), including upstream development-server and launch-editor fixes. Packaged applications run the built frontend in Tauri's WebView.

## Updating an existing installation

In **0.1.3**, the startup notice offers 0.1.4 after the preview feed advances. Choose **Download update**, then **Install and restart** after saving your edits. Settings also provides a manual check. In **0.1.2**, use **Settings → Check for updates**; **0.1.0/0.1.1** require a one-time installation of the latest preview.

The updater verifies the package signature and signed version. It replaces the application and bundled core while retaining your library and settings. It downloads a complete application package rather than differential patches. Move the macOS app to Applications first and keep Linux AppImage in a writable location. **Linux DEB installations use the package manager**. See [updating TanaHub](https://github.com/Komortes/TanaHub/blob/v0.1.4/docs/updating.md).

## Preview limits and data

- macOS builds are ad-hoc signed and not notarized; Windows installers are unsigned. Update signatures are separate from OS signing and trust warnings still apply.
- Windows/Linux packages have native build and automated core checks; interactive installation remains unverified. Real AniList OAuth and live recognition uploads still need end-to-end validation.
- No database schema migration is introduced. Close TanaHub and back up its complete app-data directory before testing a preview. Save unsaved drafts and close other copies before installing an update.

See the [installation guide](https://github.com/Komortes/TanaHub/blob/v0.1.4/docs/getting-started.md) for OS requirements, WebView2/FUSE setup and backups.
