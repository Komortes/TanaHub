# TanaHub 0.1.1 — Preview

This preview improves the first-title workflow, protects editing drafts and fixes MyAnimeList XML round trips. It includes all changes from the 0.1.0 preview. Installers include the .NET runtime; no development tools are required.

## What changed

- Recording the first episode/chapter of a new Planning title starts Watching/Reading, so it appears in Home's in-progress section. Explicit statuses and manually entered dates are preserved.
- Unsaved notes, reviews, tags, custom lists, tracking dates and progress survive navigation and reloads in the same window. Save or discard explicitly. Drafts are not included in backups and are not guaranteed after closing the window.
- Add/progress controls retain usable keyboard focus, including failed writes and the last episode/chapter.
- MAL XML previews use imported title names. Imported names and episode/chapter totals remain available offline after restarting. Known MAL IDs and media types match existing entries, avoiding duplicates when reimporting an export; existing duplicate entries are not automatically removed.
- A failed metadata write leaves the library unchanged and supports retry. Local reviews, tags and lists remain protected during import.
- Settings explains that update checks use stable releases and offers Browse releases for previews. Singular title/episode/chapter labels are corrected.

## Validation and known limits

- The fixes pass 359 .NET tests, 137 Chromium scenarios and 9 release/environment tooling tests. The release workflow checks the self-contained core and builds native installers on macOS, Windows and Linux.
- Native macOS startup, catalog access, tracking, draft recovery, persistence and CSV/MAL XML file dialogs have been exercised on isolated profiles. Interactive Windows/Linux installation and file dialogs remain unverified.
- macOS builds are ad-hoc signed and not notarized. Windows installers are unsigned; OS trust warnings are expected.
- Real AniList OAuth and live recognition uploads still need end-to-end validation. AniList imports are one-way; local changes are not sent back.
- Preview updates are downloaded manually from GitHub. The built-in update check only checks stable releases.

## Existing libraries

No database schema migration is introduced. Close TanaHub and back up its complete app-data directory before installing a preview. Use an absolute `TANAHUB_DATA_DIRECTORY` for a separate test profile. Avoid editing one profile from both desktop clients at once.

Report problems with the version, OS, architecture and reproducible steps; remove credentials and personal data from attachments. See the [release guide](https://github.com/Komortes/TanaHub/blob/v0.1.1/docs/release.md) and [smoke checklist](https://github.com/Komortes/TanaHub/blob/v0.1.1/docs/smoke-test.md).
