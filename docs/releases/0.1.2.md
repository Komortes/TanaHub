# TanaHub 0.1.2 — Preview

This preview improves artwork loading and introduces signed in-app updates. Packages include the .NET runtime; development tools are not required.

## Artwork loading

- Cards and compact rows use appropriately sized artwork, with screen density taken into account. Enlarge still opens the original cover.
- Images load near the visible area through a queue of at most four loads. A failed preview falls back to the original image.
- The desktop client caches supported provider artwork between launches, with a 256 MiB budget and an 8 MiB limit per image. Old files are evicted; after 30 days artwork is refreshed, with a saved-image fallback when the network is unavailable.
- Covers, banners, character pictures and related-title images use the shared loading path. Unknown image hosts retain normal WebView loading.

## In-app updates

Install 0.1.2 once to enable **Settings → Check for updates → Download update → Install and restart**. Earlier 0.1.0/0.1.1 installers cannot acquire an updater through their existing checker.

The app verifies the package signature and signed version before installation. Downloading and installing are separate actions, so you can save your changes before restarting. The application and bundled core are replaced while your library and settings remain in their app-data directory. The complete signed application package is downloaded; this is not differential patching.

In-app installation supports macOS, installed Windows builds and Linux AppImage. Move the macOS app to Applications first and keep Linux AppImage in a writable location. Linux DEB installations use the package manager; the app explains this and provides Browse releases. See [updating TanaHub](https://github.com/Komortes/TanaHub/blob/v0.1.2/docs/updating.md).

## Preview limits and data

- macOS builds are ad-hoc signed and not notarized; Windows installers are unsigned. Update signatures are separate from OS signing and trust warnings still apply.
- Native macOS artwork loading, persistence and startup have been exercised with isolated data. Windows/Linux have native build and automated checks; interactive installation remains unverified.
- Real AniList OAuth and live recognition uploads still need end-to-end validation.
- No database schema migration is introduced. Close TanaHub and back up the complete app-data directory before testing a preview. Save unsaved drafts before restarting, and close other copies of the app before updating.

See the [installation guide](https://github.com/Komortes/TanaHub/blob/v0.1.2/docs/getting-started.md) for OS requirements, WebView2/FUSE setup and backups.
