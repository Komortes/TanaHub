# TanaHub 0.1.3 — Preview

TanaHub now checks for updates in the background when you open the desktop app. A notice above the current page offers the new version without a trip to Settings. Packages include the .NET runtime; development tools are not required.

## Updates at startup

- Supported macOS, Windows and Linux AppImage packages check once per launch. A failed background check or an up-to-date result stays quiet so you can keep using your library.
- When an update is available, choose **Download update** or **Later**. Later hides the notice until the next launch; downloading and installing always require your action.
- Download progress follows you between pages. Settings uses the same update state and still offers a manual check or retry, without starting duplicate checks.
- After signature verification, choose **Install and restart** when your edits are saved. The notice does not take keyboard focus when it appears.

In **0.1.2**, open **Settings → Check for updates** to download 0.1.3 and install it in the app. The new startup check becomes available after this upgrade. **0.1.0/0.1.1** require a one-time installation using the packages below.

The updater verifies both the package signature and its signed version. It replaces the application and bundled core while your library and settings remain in their app-data directory. It downloads a complete application package rather than differential patches. Move the macOS app to Applications first and keep Linux AppImage in a writable location. **Linux DEB installations use the package manager**; the app explains this and offers Browse releases. See [updating TanaHub](https://github.com/Komortes/TanaHub/blob/v0.1.3/docs/updating.md).

## Preview limits and data

- macOS builds are ad-hoc signed and not notarized; Windows installers are unsigned. Update signatures are separate from OS signing and trust warnings still apply.
- Windows/Linux packages have native build and automated core checks; interactive installation remains unverified. Real AniList OAuth and live recognition uploads still need end-to-end validation.
- No database schema migration is introduced. Close TanaHub and back up its complete app-data directory before testing a preview. Save unsaved drafts and close other copies of the app before installing an update.

See the [installation guide](https://github.com/Komortes/TanaHub/blob/v0.1.3/docs/getting-started.md) for OS requirements, WebView2/FUSE setup and backups.
