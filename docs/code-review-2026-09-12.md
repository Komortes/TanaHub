# Проверка TanaHub — 12 сентября 2026

Проверены запуск Avalonia, ViewModel поиска и библиотеки, локальное хранение,
импорт, кэш каталога и загрузка изображений. Исправления оставлены в рабочем дереве.

## Исправленные ошибки

| Проблема | Исправление и проверка |
| --- | --- |
| Зависание до появления окна при импорте legacy JSON | Устранён захват UI SynchronizationContext внутри асинхронного импорта, который DI ожидал синхронно. Подтверждено стеком зависшего процесса и тестом, падавшим до исправления. |
| Повторное добавление тайтла стирало прогресс, оценку и заметки | Добавление проверяет существующую запись; общий semaphore сериализует Add и UI-импорты. Регрессионный тест проверяет сохранение полей. |
| Повтор ID внутри импорта приводил к ошибке SQLite | Убрано принудительное переключение новой EF-сущности из Added в Modified. Проверены повторы, регистр, Unicode ID и импорт более 500 записей. |
| После очистки библиотеки возвращались демотайтлы | Производственная инициализация больше не заполняет пустую библиотеку примерами. Проверены первый запуск и перезапуск пустой базы. |
| Старый ответ поиска заменял результаты новых фильтров | Отмена запросов, версия поиска и принадлежность loading-состояний конкретному запросу. Проверены смена фильтров, очистка во время поиска и пагинация. |
| Неверный ввод прогресса превращался в ноль | Некорректные, отрицательные и слишком большие числа отклоняются без записи. |
| Поздний ответ карточки возвращал пользователя на уже закрытую страницу | Ответ проверяется по версии навигации перед изменением состояния. |
| Фильтр библиотеки менял блок недавних тайтлов на Home | Home получает отдельные шесть последних записей. |
| Ошибки изображений кэшировались навсегда, file-policy обходилась через общий кэш | Кэшируются только успешные HTTP(S) изображения; локальные файлы проходят отдельную проверку и не попадают в общий кэш. |
| Кэш терял новые тайтлы при параллельном сохранении | Изменения и сохранённый snapshot отслеживаются по версиям; загрузка дискового кэша завершается до использования каталога. |

## Оптимизация

- SQLite lookup, изменение и удаление материализуют только нужную запись.
  Merge выбирает совпадающие ID пакетами и использует словарь вместо повторных
  линейных поисков. Существующая схема базы сохранена.
- Загрузка и декодирование картинок выполняются вне UI-потока, одновременно не
  более четырёх операций. Устаревшие загрузки отменяются, размер потока ограничен,
  установлен общий срок загрузки. Shared bitmap не уничтожается, пока его могут
  использовать другие контролы.
- Убран лишний поисковый запрос при старте. Запросы рекомендаций выполняются
  с ограниченным параллелизмом; библиотека обновляется до их завершения.

## Проверка и практические ограничения

- Release-сборка с предупреждениями как ошибками: 0 ошибок, 0 предупреждений.
- Полный набор тестов: 132 passed (65 Application + 67 Infrastructure), 0 failed.
  До изменений было 111 тестов.
- Ручная проверка нативной macOS-сборки: запуск, каталог с постерами, поиск по
  названию через Enter, добавление, увеличение прогресса, перезапуск с сохранением
  прогресса, библиотека в обычном и узком окне.
- Для UI-проверки использован `TANAHUB_DATA_DIRECTORY=/tmp/tanahub-ui-review`.
  Этот явный override изолирует все локальные данные на macOS; XDG_CONFIG_HOME
  не заменяет macOS Application Support.

Численные замеры FPS и времени запуска не проводились. Lookup с пользовательской
collation пока может сканировать ID в SQLite: уменьшена материализация, отдельный
индекс не добавлен. Полная загрузка и виртуализация больших библиотек остаются
отдельным направлением оптимизации. Декодер проверяет лимит пикселей после
декодирования. Live OAuth/sync с личными аккаунтами и распознавание через платные
ключи в этой проверке не запускались.
