# Связанные тайтлы: проверка источников

Обновление 27 сентября: реализация продолжена; актуальное поведение описано в [документе реализации](related-titles-implementation-2026-09-27.md). Ниже сохранены результаты исходного исследования.

Проверено 25 сентября 2026 года по коду TanaHub, официальным схемам API и живым ответам AniList и MangaDex. Здесь «серия» означает части франшизы: сезоны, фильмы, первоисточники, адаптации и спин-оффы. Отдельные эпизоды и главы рассмотрены отдельно ниже.

## Вывод

**Для блока связанных тайтлов существующих источников достаточно.** AniList покрывает связи аниме и манги; MangaDex даёт собственные связи манги и, если заполнены внешние идентификаторы, точный переход к AniList. Сейчас TanaHub эти поля не запрашивает или отбрасывает при десериализации. Полнота связей зависит от конкретной записи; два проверенных примера не доказывают полное покрытие каталога.

Новый провайдер и сервер для первой версии не нужны. Потребуются модель связей, сохранение внешних ID, отдельный кэш и компонент страницы тайтла. Полный блок навигации в рамках этой проверки ещё не реализован.

## Что есть в источниках

| Возможность | AniList | MangaDex |
| --- | --- | --- |
| Предыдущие/следующие части | `PREQUEL`, `SEQUEL` | `prequel`, `sequel` для манги |
| Первоисточник и адаптация | `SOURCE`, `ADAPTATION`, включая переход между аниме и мангой | `adapted_from`, `based_on` между записями манги; аниме можно найти через внешние ID и AniList |
| Спин-оффы и побочные истории | `SPIN_OFF`, `SIDE_STORY`, `PARENT` | `spin_off`, `side_story`, `main_story` |
| Дополнительные версии | `ALTERNATIVE`, `SUMMARY`, `COMPILATION`, другие типы | `colored`, `monochrome`, `alternate_version`, `doujinshi`, другие типы |
| Сопоставление каталогов | `id`, `idMal`, `type` | `attributes.links`, в проверенном ответе есть `al` и `mal` |
| Общее число единиц | `episodes`, `chapters`, `volumes`; возможен `null` | `lastChapter` и `lastVolume` — строки с последними номерами, не гарантированное количество |

Источники: [AniList MediaRelation](https://docs.anilist.co/reference/enum/mediarelation), [AniList Media](https://docs.anilist.co/reference/object/media), [официальная схема MangaDex](https://api.mangadex.org/docs/static/api.yaml).

Для AniList нужен `relations { edges { relationType(version: 2) node { ... } } }`: версия 2 явно предоставляет `SOURCE`. Смысл связи сохраняем относительно исходного тайтла. Нельзя механически считать каждую адаптацию переходом «манга → аниме»: бывает и обратное направление.

В MangaDex связи доступны в `relationships` карточки (`type: manga`, `id`, `related`), а также через `GET /manga/{mangaId}/relation?includes[]=manga`. Второй endpoint в проверенном ответе вернул названия связанных тайтлов вместе со связями.

## Проверка живых данных

**AniList, Attack on Titan (`16498`):** получено 11 прямых связей. Среди них `SOURCE → 53390` (манга), `SEQUEL → 20958` (Season 2), `SPIN_OFF → 21281` (Junior High), побочные OVA и фильмы. Это подтверждает основной сценарий пользователя без угадывания по названию.

**AniList, Cowboy Bebop (`1`):** получено 5 прямых связей, включая фильм (`5`) и две манга-адаптации (`30173`, `30174`). Это проверка обратного направления адаптации.

**MangaDex, Attack on Titan (`304ceac3-8cdb-4fe7-acf7-2b6ff7a60613`):** `links.al = 53390`, `links.mal = 23390`. AniList возвращает для манги тот же MAL ID `23390`. Получается точная цепочка MangaDex → AniList manga → связанные anime. [Проверенная карточка API](https://api.mangadex.org/manga/304ceac3-8cdb-4fe7-acf7-2b6ff7a60613).

У этой записи MangaDex получена 101 связь: 91 `doujinshi`, 5 `spin_off`, 2 `side_story`, по одной `prequel`, `colored`, `same_franchise`. Поэтому выводить все связи одной лентой неудобно. [Проверенный список связей](https://api.mangadex.org/manga/304ceac3-8cdb-4fe7-acf7-2b6ff7a60613/relation).

Это снимок данных на дату проверки, а не фиксированные значения для тестов или интерфейса. Уже в небольшой поисковой выборке встречались записи MangaDex с пустыми `links`: переход к AniList доступен не для каждой манги.

## Что уже умеет TanaHub и чего недостаёт

- `RoutedMediaCatalogService`: AniList по умолчанию обслуживает и аниме, и мангу. MangaDex включается для поиска манги при соответствующем выборе источника. Открытие по ID уже маршрутизируется по префиксу, независимо от выбранного источника поиска.
- `AniListMediaCatalogService`: разделяет `Anime`/`Manga`, сохраняет `MalId`, эпизоды/главы/тома, но в запросе и DTO нет `relations`.
- `MangaDexMediaCatalogService`: читает обложку из `relationships`, но не сохраняет связи манги и `attributes.links`. Внешние ID и количество глав/томов из MangaDex сейчас не попадают в модель.
- `MediaItem`: нет коллекции связей и полного набора идентификаторов провайдеров. Для MAL-импорта `Id` может оставаться `mal:manga:…`/`mal:anime:…`, поэтому нужен отдельный настоящий AniList ID.
- `OfflineCatalogCache`: связи не сериализуются. Текущая проверка полноты карточки AniList по наличию персонажей не подходит для определения, загружены ли связи. Поисковая карточка также не должна затирать более полный результат.

## Предлагаемая компоновка на нашей стороне

На странице тайтла — блок «Связанные тайтлы» с группами:

1. **Предыдущие и следующие части.** Сезоны, фильмы, OVA с явным типом связи. `PREQUEL` сам по себе не означает «сезон 0» или рекомендованный порядок просмотра.
2. **Первоисточник и адаптации.** Манга, аниме, ранобэ с указанием формата и направления связи.
3. **Спин-оффы и побочные истории.** Отдельная группа без смешивания с продолжениями.
4. **Другие версии и дополнения.** Сводки, цветные версии и прочее; додзинси — отдельная свёрнутая группа, если их вообще включаем в продукт.

Карточка: обложка, название, тип связи, формат, год, число эпизодов или глав при наличии, локальный статус и прогресс. Нажатие открывает обычную страницу тайтла. Неизвестный объём остаётся неизвестным, а не превращается в ноль. Для ранобэ надо отдельно решить, показываем ли тома; в доменной модели сейчас это `Manga` с форматом `Novel`.

Сначала достаточно прямых связей. Чтобы показать всю цепочку сезонов, нужен ограниченный обход `PREQUEL`/`SEQUEL` с защитой от циклов, дедупликацией и загрузкой по запросу. Не следует обходить `CHARACTER`, `OTHER`, `shared_universe` как основные связи: так в одну франшизу попадут посторонние тайтлы. Сортировка по полной дате релиза, которую придётся добавить в модель, должна называться порядком выхода, а не «правильным порядком просмотра».

Техническая последовательность:

1. Добавить нормализованные связи с исходным типом, провайдером, направлением и временем получения. Отдельно хранить внешние ID и состояние загрузки (`не загружено`, `загружено пусто`, `ошибка`).
2. Получать связи при открытии деталей и кэшировать отдельно от кратких поисковых результатов. Соблюдать ограничения API и `Retry-After`; не запрашивать рекурсивно всю франшизу при каждом переходе.
3. Для MangaDex использовать `links.al`, затем `links.mal` с `type: MANGA` для поиска в AniList. Проверять тип результата. MAL ID обязательно хранить вместе с типом медиа.
4. Сводить одинаковые карточки по точным ID, сохраняя источник каждой связи. Связанные сезоны и адаптации остаются разными произведениями с отдельным прогрессом. Существующие записи библиотеки с разными ключами не сливать молча.
5. Учитывать смену текущей страницы: поздний ответ старого тайтла не должен менять новый экран или показывать на нём уведомление. Загрузка связей имеет собственное состояние, основная карточка остаётся доступной.

Если точных ID нет, показывать известные связи исходного провайдера. Возможное расширение — локальные подтверждённые пользователем связи и таблица соответствий. Поиск по похожему названию можно использовать для предложения кандидатов с проверкой автора, формата и года, но не для автоматического объединения. Дополнительный API не решает отсутствие надёжного соответствия сам по себе.

## Если нужен список отдельных эпизодов и глав

Это отдельная задача. AniList предоставляет общее количество, расписание выхода и ссылки на доступные легальные стриминговые эпизоды; `streamingEpisodes` нельзя считать гарантированным полным справочником названий всех серий. [Описание полей AniList](https://docs.anilist.co/reference/object/media).

MangaDex предоставляет `/manga/{id}/feed` и `/manga/{id}/aggregate` для глав и томов с фильтрами языка/группы. Нужно различать главу и её несколько переводов, учитывать дробные номера вроде `15.1`, недоступные главы и сброс нумерации между томами. `lastChapter = 139` не доказывает наличие ровно 139 читаемых глав. [Схема MangaDex](https://api.mangadex.org/docs/static/api.yaml).

В качестве дополнительного источника изучен **Jikan v4**. В его официальной схеме есть `/anime/{id}/episodes`, `/anime/{id}/relations`, `/manga/{id}/relations`; ключ — MAL ID, который у нас уже есть для AniList. Пробный живой запрос `/anime/1/episodes?page=1` завершился HTTP 504, поэтому фактическое покрытие эпизодов этим запросом не подтверждено. По схеме это кандидат для списка эпизодов и резервных связей. Jikan — неофициальный API MyAnimeList; он добавляет внешнюю зависимость. Документированные лимиты — 3 запроса/секунду и 60/минуту, кэш сервиса — 24 часа. [Документация Jikan](https://docs.api.jikan.moe/), [схема API](https://github.com/jikan-me/jikan-rest/blob/master/storage/api-docs/api-docs.json).

Первая версия связанных тайтлов реализуема на текущих источниках. Если нужен также каталог эпизодов, предлагается AniList + MangaDex + необязательный адаптер Jikan с пагинацией, кэшированием и явным состоянием отсутствующих данных.

## Исправление терминологии

В этой работе исправлены подписи текущего статуса, иконка прогресса, примеры тегов и единицы прогресса в деталях, библиотеке и на главной: для манги используются Reading, Chapters, +1 Chapter, ch.; для аниме — Watching, Episodes, +1 Episode, ep. Для повторного прохождения в списках — Rereading/Rewatching. Настройка релизных уведомлений описывает реально поддерживаемые эпизоды аниме.

Проверки: 152 теста пройдены (85 Application, 67 Infrastructure); desktop-сборка проходит без предупреждений и ошибок. Отдельный визуальный прогон этих текстовых изменений не выполнен.
